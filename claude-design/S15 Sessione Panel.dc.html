Concetto core

Nel tuo file ColorCode sull'event loop il codice chiama la funzione sbagliata e rende false tutte le annotazioni — nessuno l'ha mai eseguito. È il caso di studio perfetto del modulo: qui l'asincronia smette di essere magia e diventa un modello meccanico (call stack, task queue, microtask queue) che sai girare a mano. Senza questo modello, promises e async/await (unità 0.8) restano sintassi vuota — è la priorità alta dichiarata in diagnosi.

TeoriaFondamenta Event loop: microtasks and macrotasks — javascript.infojavascript.info

Il modello completo con le regole di priorità (i microtask vengono svuotati TUTTI prima del prossimo task). Traccia a mano gli esempi del capitolo col tuo formato stato-per-iterazione: stack | coda task | coda microtask, riga per riga. È la traccia manuale che in diagnosi risulta il tuo strumento più efficace.

StudioVisualizzazione What the heck is the event loop anyway? — Philip Roberts, JSConf EUyoutube.com · 26 min

IL talk di riferimento mondiale sull'event loop (26 minuti, tutto animato). Philip Roberts costruisce il modello mentale della singola corsia e delle code visivamente, dal vivo. È la spiegazione che rende il concetto tuo per sempre; guardalo con il quaderno accanto e ferma il video per anticipare la prossima mossa.

PraticaTesting & Debugging Loupe — visualizzatore live dell'event loop (Philip Roberts)latentflip.com

Lo strumento che esegue codice VERO mostrando stack, coda e Web API in movimento. Flusso di lavoro: scrivi un frammento (log sincroni, setTimeout a zero, catene), PREVEDI l'ordine dei log sul quaderno, premi play, osserva. È il tuo formato-esperimento elevato a laboratorio. Poi l'atto riparatore: riapri il TUO file event loop di ColorCode, eseguilo com'è, osserva perché le annotazioni sono false, correggi con la data.

Mini progettoBatteria di previsioni: 10 su Loupe JavaScript Visualized: Event Loop — Lydia Hallie (dev.to)dev.to

Usando l'articolo animato di Lydia Hallie come riferimento delle regole, crea un documento nel repo di studio con 10 frammenti a difficoltà crescente. Loupe visualizza solo call stack + Web API + coda dei task (setTimeout) — non le promise/microtask; in questa unità la batteria è solo macrotask (sincroni + setTimeout); i frammenti con promise si aggiungono DOPO l'unità 0.8. Registro degli errori: ogni previsione sbagliata è una crepa del modello da rispiegare.

Ambito · Unità 0.7
In quale ordine escono i log di: codice sincrono, un setTimeout a zero e una promise già risolta?
Prima il codice sincrono, poi la callback della promise, per ultimo il setTimeout. La promise risolta accoda un microtask, e i microtask vengono svuotati tutti prima che il prossimo task (il timer) entri nella corsia.12
